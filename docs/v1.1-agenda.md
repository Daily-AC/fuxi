## 1 · U1 · 视觉疲劳 · 产品经理视角重想

你的反馈："清爽了但费眼"。根因诊断：

1. **视觉权重太均匀** —— 每行一个竖条 = 信息密度=视觉密度，大脑分不出"新 / 重要 / 需关注"
2. **颜色饱和度太高** —— mauve (#cba6f7) + teal (#94e2d5) 都在高饱和段，长时间盯屏刺眼
3. **消息无边界感** —— 没有消息间空行/分隔，一大片竖条像"条形码"

### 三个替代方案（成本由低到高）

#### 方案 A · 竖条只在首行 + 时间戳锚点（推荐先上）

```
▍ 12:03  你收到抄送了吗？
         续行对齐，不带竖条

▍ 12:03  收到了，两次—
         1. 鲁班刚 spawn 完那下…
         2. 刚才数完 20 又抄了一次
```

- **一条消息一个 `▍` 锚点**，续行用空格对齐（回到之前你觉得"玄女 + tab 空太多"的反面——现在不是 tab 缩进而是短短 3-4 格）
- **时间戳**给消息"位置感"，浏览时眼睛在 `12:03` 锚点上定位，不再扫竖条
- **消息间保留一个空行**，视觉呼吸
- **饱和度降档**：user 用 `sapphire` 代替 `teal`（更沉静），agent 用 `lavender` 代替 `mauve`（更柔和）
- 实现成本：小，改 render_dialogue_collapsed 一处 + theme 再加两个 alias
- **验证方法**：对话 20 条后连看 30 秒不累就算过关

#### 方案 B · 消息气泡（中成本）

```
┌───────────────────
│ 你   12:03
│ 你收到抄送了吗？
└───────────────────

┌───────────────────
│ 玄女  12:03 · cc
│ 收到了，两次—
│ 1. 鲁班刚 spawn…
└───────────────────
```

- 每条消息独立 Block，mantle 灰底（Catppuccin 次级背景色）
- 有明确"一条 = 一个容器"的语义，最像 iMessage
- 改动大：要跨 Block 布局、滚动算法得重写（当前是单一 Paragraph，要切换成 Vec<Paragraph>）
- 成本估：1 天

#### 方案 C · Claude Code 风格 transcript（最高成本，对应 v1.2 "事件流嵌入对话"）

```
> 12:03  你收到抄送了吗？

●  12:03  玄女
  收到了，两次—
  1. 鲁班刚 spawn 完…

◈  12:04  Bash(fuxi status)
  ↳ luban | idle | 0 tasks

✓  12:04  Done (3m12s)

▎  12:05  新任务：起一个鲁班门客
```

- 事件 / 消息 / 工具调用 / 任务状态**全部混在同一 transcript**
- 取代左下角事件面板——左栏可以砍到只剩任务树或更简
- **这是 §10 第 3 条 "学 cc/opencode/codex 单栏"的技术落地**
- 成本估：2-3 天（含测试、ClickRegistry 升级、滚动 pre-wrap 精度）

### 推荐

**A 先上（0.5 天立竿见影）→ 然后 C（v1.2 大改）**。B 作为 A 到 C 过渡的备胎，不直接上。

## 3 · §13 架构审查请求

你说："**架构乃地基，打不好永远是危房**" —— 我同意。审查应作为**独立 session** 做，交付如下：

3. **对照 v1 蓝图找差距**（`docs/architecture-v1.md`）
4. **参考借鉴**：
   - `claw-code`（你给的 repo）—— 看 Rust 组织方式
   - **ComposioHQ**（公理 #6 提到的智慧源）—— 对比 tool 设计
   - Claude Code / opencode / codex 的 CLI 分层

### 产出分类

- 🔴 **必须改**（安全/正确性）—— 例如 N1 消息黑洞、session lock 竞态
- 🟡 **应该改**（一致性/可维护）—— 例如 N7 命名对冲、N8 参数风格
